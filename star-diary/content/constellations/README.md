# 별자리 이야기 DB — 편집 가이드

여기 있는 `*.md` 10개가 앱이 쓰는 신화·철학 재료의 **원본**입니다. 메모장이나 VS Code로 열어 자유롭게 고치세요. 따옴표·쉼표 신경 쓸 필요 없습니다.

고친 뒤 반영: `star-diary` 폴더에서 `npm run content` (배포 시엔 자동 실행). 형식이 어긋나면 어느 파일의 어떤 항목인지 알려줍니다.

## 파일 형식 (줄 이름은 바꾸지 말 것)

```
# 별자리 이름
페르소나: 한 단어~한 구절
한 줄: 페르소나를 설명하는 한 문장 (선택 화면에 보임)
톤: 고쳐보기 / 정리하기 / 넓히기 / 지키기 중 하나

## 신화
자유롭게. 여러 문단 가능.

## 표면적 교훈
한 줄.

## 철학
철학자: 이름
개념: 개념 이름(괄호 안 짧은 풀이)
풀이: 고등학생용 한두 문장 + 비유 하나
조언 방향: 이 별자리가 사용자에게 제안하는 방향 (한 줄)
```

## 신화를 쓸 때 (LLM이 이걸 재료로 다시 씀 — 재료가 좋아야 결과가 좋음)
- **인과가 보이게**: "황금 비가 되어 스며들었다" ✗ → "신들의 왕이 탑에 갇힌 그녀에게 닿으려고 황금 비로 변해 들어왔고, 그렇게 아이가 태어났다" ✓
- **이름은 주인공 외 2명까지**, 첫 등장에 "역할 + 이름"(지혜의 여신 아테나). 나머지는 역할만(섬의 왕, 전령의 신)
- **장면·사물·대사**를 남길 것: "거울처럼 닦은 방패", "죽은 자의 발은 소리가 없다" 같은 디테일이 개인화의 재료가 됨
- 마지막 문단은 **별자리가 하늘에 어떻게 남았는지**로
- 분량 600~900자. 요약체("~했다. ~했다.")보다 이야기체
- 페르소나의 행동 패턴(예: 완주 직전 의심)이 **신화의 어느 장면**에 있는지 분명하게 — 그 장면이 "당신이 서 있는 자리"가 됨

## 철학 풀이를 쓸 때
- 개념 이름 → 한 문장 정의 → 일상 비유 하나. 고등학생이 처음 들어도 이해되게
- "조언 방향"은 "~하지 마라"가 아니라 방향·타이밍·순서를 바꾸는 말로

## 바꾸면 안 되는 것
- 파일 이름(id)과 `# 별자리 이름` — 코드의 별 좌표·프로필과 연결돼 있음
- 톤 4종 외의 값
